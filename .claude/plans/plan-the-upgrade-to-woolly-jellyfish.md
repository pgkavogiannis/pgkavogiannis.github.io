# Plan: Upgrade to Yarn 4 (Modern Yarn / Berry)

## Context

The project currently uses Yarn Classic 1.22.22, pinned via Volta. Yarn Berry (4.x) is the modern successor with faster installs, better deduplication, workspace protocol improvements, and active maintenance. Yarn 1 is in maintenance-only mode.

The safest migration path for a Next.js project is **Yarn 4 with the `node-modules` linker** — this keeps the familiar `node_modules/` layout and is a near-drop-in replacement. PnP (the default Berry mode) requires additional tooling compatibility work and is intentionally out of scope here.

---

## Changes Required

### 1. Initialize Yarn Berry in the project

```bash
yarn set version stable         # writes .yarn/releases/yarn-X.Y.Z.cjs + .yarnrc.yml
yarn --version                  # confirm 4.x
```

### 2. `.yarnrc.yml` — set node-modules linker

After `yarn set version stable` creates `.yarnrc.yml`, set:

```yaml
nodeLinker: node-modules
```

This is the only required config key; it makes Yarn 4 behave identically to Classic for `node_modules` consumers.

### 3. `package.json` — two updates

**a) `packageManager` field** (enables corepack auto-install, standard for Berry):
```json
"packageManager": "yarn@4.x.y"    ← exact version from yarn --version
```

**b) Update Volta pin** (replace 1.22.22 with the new Berry version):
```json
"volta": {
  "node": "24.16.0",
  "yarn": "4.x.y"
}
```

### 4. Regenerate `yarn.lock`

```bash
yarn install    # migrates v1 lock → v2+ lock format
```

Verify no install errors before proceeding.

### 5. `.gitignore` — add Berry-specific entries

Yarn Berry stores the binary in `.yarn/releases/` (should be committed) and creates `.yarn/install-state.gz` (should be ignored). Append to `.gitignore`:

```
# Yarn Berry
.yarn/cache
.yarn/unplugged
.yarn/build-state.yml
.yarn/install-state.gz
.pnp.cjs
.pnp.loader.mjs
```

Commit `.yarn/releases/yarn-X.Y.Z.cjs` — this is intentional; it makes the project self-contained.

### 6. `.github/workflows/deploy.yml` — replace manual Yarn install

**Remove:**
```yaml
- name: Install Yarn
  run: npm install -g yarn@1.22.22
```

**Replace with:**
```yaml
- name: Enable corepack
  run: corepack enable
```

Node 24 ships corepack; it reads `packageManager` from `package.json` and auto-installs the correct Yarn 4 version. No `npm install -g yarn` needed.

Also update the cache path if it references `~/.yarn/cache`:
```yaml
- uses: actions/cache@v4
  with:
    path: .yarn/cache          # Berry stores cache here, not ~/.yarn/cache
    key: ${{ runner.os }}-yarn-${{ hashFiles('yarn.lock') }}
```

### 7. `.github/workflows/nextjs.yml` — verify detection still works

This workflow auto-detects the package manager by checking for `yarn.lock`. It should continue to work without changes, but confirm `cache: yarn` still resolves after the lock format upgrade.

### 8. Husky / lint-staged — no changes expected

With `nodeLinker: node-modules`, husky still installs to `node_modules/.bin/husky` and `yarn lint-staged` in `.husky/pre-commit` continues to work identically. No changes needed.
